## Key Findings

### What went well
- Blast radius is fully contained — Kafka chaos never affected Postgres or Redis
- `redis-down` scenario confirmed the `try/catch` fix in `alerts.service.ts` works correctly. Redis failure is non-fatal; alerts are preserved in Postgres
- `kafka-down` connection reset confirmed DLQ path will trigger in real broker failure
- Toxiproxy proxy registration and toxic injection/removal are fully automated via `make chaos-*`

### What we learned
- TCP connect-time latency measurements are insufficient — data-path RTT must be used (Kafka ApiVersions request, psql query, Redis PING protocol)
- Prometheus assertions require running app services; infra-level assertions (pg_up, pg_stat_activity_count) work without them

- N/A — all scenarios behaved as designed
