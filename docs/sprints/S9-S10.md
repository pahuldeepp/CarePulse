# Sprint S9–S10 (Release R5)

**Milestone (per [README.md](../../README.md)):** Monthly incident drill · error budget policy active.

Two-sprint window, four weeks. S9 lands the measurement + policy foundation; S10 turns it into a repeatable drill.

---

## S9 — SLOs & Error-Budget Policy (Wk 17-18)

Goal: every prod-bearing service has a written SLO, a burn-rate alert wired to Prometheus, and an enforced error-budget policy.

### Tickets

- **S9-01 — SLO catalogue.** One `slo.yaml` per service under `infra/slo/<service>.yaml`. Fields: `sli`, `target` (e.g. 99.9% over 30d), `window`, `owner`. Start with: gateway-graphql, patient-service, telemetry-ingest, workflow-alerts, risk-engine, fhir-gateway, billing-service.
- **S9-02 — Burn-rate alert rules.** `infra/docker/prometheus/rules/burn-rate.yml` — fast (1h, 14.4× burn) and slow (6h, 6× burn) windows per SLO. Multi-window multi-burn-rate per Google SRE workbook.
- **S9-03 — Wire rules into Prometheus.** Add `rule_files:` to [prometheus.yml](../../infra/docker/prometheus/prometheus.yml); add service scrape configs (currently only postgres + prometheus self-scrape).
- **S9-04 — Service /metrics endpoints.** Audit each service: confirm a `/metrics` endpoint exists with `http_requests_total` + latency histogram (OpenTelemetry → Prometheus exporter). File issues per service that lacks it.
- **S9-05 — Error-budget policy doc.** `docs/sre/error-budget-policy.md`: thresholds for feature-freeze (budget exhausted → only reliability work merges), rollback triggers, who declares an incident.
- **S9-06 — Grafana SLO dashboard.** Extend [slo.json](../../infra/docker/grafana/dashboards/slo.json) with per-service burn-rate panels and remaining-budget gauge.
- **S9-08 — Fix workflow-alerts dual-write hazard (clinical safety).** See [ADR-0005](../../adr/0005-read-side-store-selection.md). Move DynamoDB write off the request path into a Kafka consumer on `domain.alert.*` so a DynamoDB outage cannot silently break the NHS NEWS2 escalation chain.
- **S9-07 — Runbook template.** `docs/runbooks/_template.md` with sections: symptoms, diagnosis queries (Kafka lag, DB CPU, OTel trace search), mitigations, rollback. Land 3 concrete runbooks: kafka-consumer-lag, postgres-rls-deadlock, debezium-connector-down.

### Definition of done

- [x] `slo.yaml` exists for ≥7 services. (CI lint job still TODO — minor.)
- [x] Burn-rate rules written for all 7 services. **Firing requires S9-04 metrics emission — partial.**
- [x] Error-budget policy committed at [docs/sre/error-budget-policy.md](../sre/error-budget-policy.md). Sign-off pending.
- [x] 3 runbooks committed: gateway-graphql-availability, kafka-consumer-lag, debezium-connector-down.
- [x] **S9-08 dual-write hazard fixed** + integration script written.
- [x] S9-04 all 7 services instrumented (gateway-graphql + 3 NestJS + 1 Go + 2 FastAPI).
- [x] Tabletop test scripted ([tabletop-burn-rate.sh](../../scripts/sre/tabletop-burn-rate.sh)) + Makefile targets. **Actual run requires docker-compose stack — user task.**

## S10 — Incident Drill Automation (Wk 19-20)

Goal: a monthly drill runs from a script; chaos events are observable; on-call has a rehearsed flow.

### Tickets

- **S10-01 — Chaos scenarios.** `infra/chaos/scenarios/` — YAML for: kill-broker (Kafka), pause-debezium, postgres-fsync-storm, redis-network-partition. Use Toxiproxy or `pumba` against the docker-compose stack.
- **S10-02 — Drill runner.** `scripts/incident-drill.sh` — pick a scenario, inject, time-to-detect (alert fires), time-to-mitigate (script exit), produce a JSON report.
- **S10-03 — Drill report template.** `docs/drills/_template.md` + commit the first dry-run report under `docs/drills/2026-06-drill.md`.
- **S10-04 — On-call rotation doc.** `docs/sre/on-call.md` — escalation tiers, paging tool (TBD: PagerDuty vs Opsgenie — needs decision in ADR-0004), handover checklist.
- **S10-05 — Synthetic probes.** Add a `synthetic-probe` job (k6 or simple cron'd curl) hitting the golden path: login → create patient → vitals ingest → alert ack. Feeds availability SLI directly.
- **S10-06 — Postmortem template.** `docs/postmortems/_template.md`: timeline, contributing factors, action items with owners + due dates. Blameless framing.
- **S10-07 — Game-day #1.** Schedule and execute the first end-to-end drill on the staging stack. Publish the postmortem even if nothing broke.

### Definition of done

- [ ] One full drill executed and postmortem committed.
- [ ] Drill runner produces a machine-readable report.
- [ ] On-call doc names primary/secondary placeholders (real names redacted in repo).
- [ ] Synthetic probe SLI feeds the Grafana dashboard from S9-06.
